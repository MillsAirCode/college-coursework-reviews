# The-Gaming-Room

I built this for CS230, fall 2023. It was a design-focused project for a gaming platform, attempting to cover requirements for user libraries, chat, discovery, and live streaming.

The project documentation is okay—the requirements were clear and I did a decent job at mapping them to a design. I was successful at identifying user needs through some basic analysis and trying to create a scalable structure.

Looking back, the "design" is basically just a collection of static requirements and high-level concepts. There's no actual implementation to speak of here—no database, no real-time chat, no streaming logic. It's just a blueprint for a service that doesn't exist. I was clearly more focused on the "design doc" part of the rubric than actually building anything functional. If I were doing this today, I'd focus much more on the technical architecture of the chat and streaming components instead of just listing them as "requirements."

**Portfolio take.** It's a clean example of how to approach requirement gathering for a software project, but as a piece of software, it's just an empty shell. Useful for showing I can follow a design lifecycle, but don't expect any real code here.
