# Testing-and-automation-CS320

https://github.com/MillsAirCode/Testing-and-automation-CS320

## what it was

SNHU CS-320 (Software Test Automation & QA), fall 2023. A mobile app project covering Contacts, Appointments, and Tasks features, with a focus on JUnit unit testing. The actual Java source files (Contact.java, ContactService.java, ContactTest.java, ContactServiceTest.java) were never committed — all four are zero bytes. The repo's real content is a templated README with a personal reflection and a Project 2.docx writeup describing the testing approach.

## what holds up

The reflection in the docx shows I understood the three core testing techniques: boundary testing, exception testing, and positive testing. The idea of testing from a user's perspective rather than a developer's bias was a real insight — unit tests as an objective measure of functionality, not just a checkbox. The emphasis on null checks and string length boundaries was solid for the time.

## what I'd refactor

The repo is embarrassing. Four source files, all empty. The README is half template text with placeholder comments like "Add a brief description of your specific project goals here once files are provided." I submitted a Word doc as the actual assignment content instead of inline Markdown. The testing techniques described (boundary, exception, positive) were correct in theory but the writeup leans heavily on academic filler — "immense amount of caution," "cornerstone of quality software engineering." I clearly didn't grasp the difference between adapter and repository patterns yet, and the whole thing reads like someone trying to hit a word count rather than document actual engineering decisions.

## portfolio take

Archive. The concepts are sound but the execution is a student artifact with zero code. Not worth keeping on a public profile.
