# CS405: Secure Coding Review

I put this together for my CS405 course, focusing heavily on the theoretical side of secure development—stuff like OWASP principles, Zero Trust, and threat modeling. The goal was to show how security should be baked into the SDLC rather than tacked on at the end.

The core concepts actually hold up. The idea that "security is not an afterthought" is something I still advocate for constantly. The breakdown of threat modeling and the importance of the principle of least privilege are still the fundamentals of everything I do when building systems now.

Looking back, it's incredibly heavy on documentation and theory. I spent a lot of time talking about *what* security should look like (policy, standards, etc.) without necessarily demonstrating the "how" through code or automated tooling. If I were doing this today, I'd focus much more on implementing security-as-code—things like SAST/DAST integration in a CI/CD pipeline or writing actual exploit proofs to demonstrate why a specific vulnerability matters. It's a bit too "compliance-heavy" and not "hacker-enough."

**Portfolio take.** It's a solid demonstration that I understand the industry-standard frameworks and the theoretical foundations of secure development. It's useful for showing I can speak the language of security professionals, even if the implementation side is a bit thin on actual code.
